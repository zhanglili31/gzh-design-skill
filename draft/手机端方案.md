# 手机上也能排出好版：gzh-design 上手机的三条路

> 状态：草案（2026-09-17），未落地，待用户确认路线后再动手。

## 卡住的不是排版，是那一次「粘贴」

现在的链路是四步：写稿 → AI 按主题排版 → 出内联样式 HTML → 预览页点「复制」→ 公众号编辑器粘贴。

搬到手机上，三处会断：

1. AI 跑不起来 —— skill 需要 Claude Code / Codex 这类 Agent 环境，手机上没有。
2. 产物拿不到 —— HTML 文件躺在 Mac 上，手机看不见。
3. 粘贴掉样式 —— 现有 ADB 发布链路只能往手机剪贴板写纯文本，富文本注入不进去，精致排版全掉，只能在 App 工具栏手工补加粗。

前两条是工程问题，加点活就能解决。第三条是平台能力问题，也是真正的卡点：订阅号助手的编辑器只有加粗、下划线、斜体、五种颜色、几档字号，它压根不是为承接内联样式富文本设计的。

## 三条路

### 路线一 · 手机浏览器里闭环

预览页放到手机能打开的网址，Chrome 打开点「复制」，再在同一个 Chrome 里用「请求桌面版网站」打开公众号后台，编辑器里粘贴。

稳在于剪贴板不跨 App：复制和粘贴都发生在 Chrome 内部，text/html 原样传递。代价是小屏操作 PC 后台比较别扭，平板或折叠屏体验会好很多。

要改的东西不多：给预览页加移动端适配（大按钮、clipboard.write 带 text/html、execCommand 兜底），产物自动发到 Pages 并附二维码。

### 路线二 · 草稿箱 API 直推

服务端调草稿箱接口把正文 HTML 推成草稿，手机打开订阅号助手进草稿箱，点群发就完事。

全程不经过任何编辑器，样式百分百保留 —— skill 产出的格式本来就是这个接口要的内联 HTML。

门槛两条：未认证的个人订阅号调用会直接报 48001，必须先做微信认证；接口还要配 IP 白名单，R730 有固定出口，这条不难。

### 路线三 · 订阅号助手里直接粘

手机浏览器复制，切到订阅号助手，正文区长按粘贴。

成不成取决于它的 WebView 编辑器认不认 text/html。从它只有五种颜色三档字号看，大概率会做归一化把内联样式洗掉。这条必须实测才有结论，半小时能测完，值得先测 —— 一旦通了，它是体验最好的一条。

## 推荐组合与落地顺序

先实测路线三，再做路线一，路线二作为终局。

1. 半小时：用 ADB 把一份带样式的富文本写进手机剪贴板，在订阅号助手里粘一次，看样式掉不掉。
2. 半天：改预览页脚本出移动版，产物自动推到 Pages，交付时附二维码。
3. AI 环节：手机上用 Claude Code Web 打开这个仓库跑排版，或者做个远程触发让 Mac 干活。
4. 终局：号认证后接草稿箱接口，彻底免掉粘贴这一步。

## 写在最后

需要你拍板一件事：公众号是个人订阅号，还是已经做过微信认证？这决定路线二能不能走 —— 能走就是终局解，不能走就老老实实在路线一和路线三里挑。
