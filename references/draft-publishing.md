# 公众号草稿箱发布

仅当用户明确要求「推草稿箱」或「发布公众号」时使用本流程。排版本身不触发任何外部写操作。

## 发布前门禁

1. 先完成 `validate_gzh_html.py`，必须是 `ERROR×0`、半角标点 `WARNING×0`。
2. 从文章 `# 标题` 取草稿标题；作者、摘要、封面沿用用户给出的内容。标题或目标账号不明确时才询问：标题不明会生成错误草稿，多账号会投错号。
3. 凭证只从 `credvault` 获取。先运行 `cred list <账号关键词>`；若存在多个匹配账号，停下让用户选择。不要读取或打印凭证值。
4. 确认环境已提供下列配置；缺任何一项即停止并报告缺失项，不回退为手机编辑：

   - `GZH_WECHAT_API_BASE`：公众号 API 根地址。
   - `GZH_WECHAT_SOCKS5_PROXY`：已启动、且位于白名单出口上的 SOCKS5 代理地址。

脚本只探测该出口，绝不启动、重载或修改任何代理 / VPN / SSH 隧道。

## 推送

```bash
python3 <SKILL_ROOT>/scripts/push_draft.py <正文.html> \
  --title '<文章标题>' \
  --appid-credential '<appid 凭证名>' \
  --appsecret-credential '<appsecret 凭证名>'
```

如用户提供，追加 `--author`、`--digest`、`--cover`。脚本会通过配置的 SOCKS5 出口请求接口、上传封面和正文中的本地图，再新建草稿。封面未提供时会生成临时占位封面；临时文件在上传后删除。失败日志默认写入系统临时目录的 `gzh-publish.log`，也可用 `GZH_WECHAT_LOG_PATH` 指定。

成功标准是脚本以 `0` 退出并返回 `media_id`。随后只告知用户：打开手机「订阅号助手 → 草稿箱」，选择相同标题的草稿并群发；不要让用户重新编辑正文。

遇到 API 拒绝、白名单错误、缺凭证或上传失败时，立即停止并输出该步骤的错误；不得在未授权下替换账号、修改代理/VPN 配置、或重试发布。
